I'm OK: Daily Check-in privacy

This page describes what appears in the app's audited source code. It does not claim more than the project can verify.

Where data is stored

The app uses Apple's CloudKit through the iCloud.com.paoloac.imok.I-m-OK container. Shared statuses, chat messages and shared photos are stored in CloudKit records: the owner's private database and the shared database of contacts who accepted the invitation.

The developer does not receive or store this data on an own server. According to the flow shown in the code, the data is stored through Apple's CloudKit services associated with the participating iCloud accounts.

The code contains no own backend, own web API, Firebase, Sentry, analytics SDK, advertising SDK or StoreKit. This was checked in the source and project files, not in the compiled binary or Apple's production configuration.

Preferences, local history, pending invitations and local copies of photos and messages are also stored on the device. The code does not contain an upload of the full Contacts address book.

One-shot location

The feature uses CLLocationManager inside LocationStatusService. Permission is requested only when the user selects the “I'm Here” location message and the app prepares that check-in. It is not requested when the app opens, during onboarding or as continuous background location.

With When In Use permission, the code calls requestLocation() once. It then uses CLGeocoder to obtain a locality. If no locality is available, it uses a coordinate string as a fallback.

Using the coordinate and locality, it creates an Apple Maps URL in this format: https://maps.apple.com/?ll=latitude,longitude&q=locality. The final message contains the selected message, locality and that URL.

In a normal check-in, that text may be saved to CloudKit. In external mode, the user manually opens the SMS composer or system share sheet; the text and URL may pass to the channel chosen by the user, including WhatsApp if it is available.

The code does not show an own geocoding endpoint. The repository cannot verify what network processing Apple performs internally for the CLGeocoder service.

System permissions and capabilities

  • Contacts: choose a person with a phone number or email to prepare an invitation. The pending invitation is stored locally.
  • Camera: capture a photo, compress it and optionally send it as a CKAsset.
  • When In Use location: resolve one location for the “I'm Here” message.
  • Notifications: local alerts, sound and badge. The app also registers for remote notifications and uses silent CloudKit subscriptions to refresh data.
  • iCloud/CloudKit: share and synchronize statuses, photos and chat.
  • App Group and Live Activities: share local status with the widget and show the activity in the system.

No photo-library permission was found in the audited Info.plist. The check-in photo is captured through the camera.

Alerts and limits

CloudKit push is silent and refreshes the app. The visible alert is created by UserNotifications on the device that receives or monitors the status. The code contains no own server that automatically sends SMS or WhatsApp when a threshold passes.

If the confirming person's phone is off, no automatic SMS or WhatsApp is sent for that reason. If the contact's device already synced the latest status, it may have a local alert scheduled; delivery depends on that device, iOS, the network and its permissions.

Without a network, the check-in may temporarily update the local interface, but the code does not implement a persistent retry queue for saving the change to CloudKit. If notifications are disabled, local alerts are not shown.

What the code cannot verify

  • The repository cannot verify Apple's CloudKit retention, internal access or operational conditions.
  • The published binary's behavior and Apple's production push and CloudKit configuration were not independently verified.
  • The privacy label declared in the App Store is not treated as proof of source-code behavior and is not reproduced here as “we collect no data”.
