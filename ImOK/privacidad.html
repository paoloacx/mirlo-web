Privacidad de Estoy bien: Aviso diario

Esta página describe lo que aparece en el código fuente auditado de la app. No afirma más de lo que puede comprobarse en el proyecto.

Dónde se guardan los datos

La app usa CloudKit de Apple mediante el contenedor iCloud.com.paoloac.imok.I-m-OK. Los estados, los mensajes del chat y las fotos compartidas se guardan en registros de CloudKit: la base privada del propietario y la base compartida de los contactos que han aceptado la invitación.

El desarrollador no recibe ni almacena estos datos en un servidor propio. Según el flujo que aparece en el código, los datos se guardan mediante los servicios CloudKit de Apple asociados a las cuentas de iCloud que participan.

El código no contiene un backend propio, una API web propia, Firebase, Sentry, SDK de analítica, SDK de anuncios ni StoreKit. Esta comprobación se ha hecho sobre el código y los archivos del proyecto, no sobre el binario compilado ni sobre la configuración de producción de Apple.

Ubicación puntual

La función usa CLLocationManager dentro de LocationStatusService. El permiso se solicita solo cuando la persona selecciona el mensaje de ubicación “Estoy aquí” y la app va a preparar ese check-in. No se solicita al abrir la app, durante el onboarding ni como ubicación continua en segundo plano.

Con el permiso When In Use, el código llama una vez a requestLocation(). Después usa CLGeocoder para obtener una localidad. Si no consigue una localidad, usa una representación de las coordenadas como alternativa.

Con la coordenada y la localidad crea una URL de Apple Maps con este formato: https://maps.apple.com/?ll=latitud,longitud&q=localidad. El texto final del mensaje contiene el mensaje elegido, la localidad y esa URL.

En un check-in normal, ese texto puede guardarse en CloudKit. En el modo externo, el usuario abre manualmente el composer de SMS o la hoja de compartir del sistema; el texto y la URL pueden pasar al canal que el usuario elija, incluido WhatsApp si aparece disponible.

El código no muestra un endpoint propio para la geocodificación. No puedo comprobar desde el repositorio qué tratamiento de red realiza internamente el servicio de Apple asociado a CLGeocoder.

Permisos y capacidades del sistema

  • Contactos: elegir una persona con teléfono o email para preparar una invitación. La invitación pendiente se guarda localmente.
  • Cámara: capturar una foto, comprimirla y enviarla opcionalmente como CKAsset.
  • Ubicación When In Use: resolver una única ubicación para el mensaje “Estoy aquí”.
  • Notificaciones: alertas, sonido y badge locales. La app también se registra para remote notifications y usa suscripciones silenciosas de CloudKit para refrescar datos.
  • iCloud/CloudKit: compartir y sincronizar los estados, las fotos y el chat.
  • App Group y Live Activities: compartir el estado local con el widget y mostrar la actividad en el sistema.

No se ha encontrado un permiso de biblioteca de fotos en el Info.plist auditado. La foto del check-in se captura mediante la cámara.

Avisos y límites

El push de CloudKit es silencioso y sirve para refrescar la app. La alerta visible la crea UserNotifications en el dispositivo que recibe o monitoriza el estado. El código no contiene un servidor propio que envíe automáticamente SMS o WhatsApp cuando vence un plazo.

Si el teléfono de quien confirma está apagado, no se envía por ese motivo un SMS o WhatsApp automático. Si el dispositivo del contacto ya sincronizó el último estado, puede tener programado un aviso local; su entrega depende de ese dispositivo, de iOS, de la red y de sus permisos.

Sin red, el check-in puede actualizar temporalmente la interfaz local, pero el código no implementa una cola persistente de reintento para guardar el cambio en CloudKit. Si se desactivan las notificaciones, los avisos locales no se muestran.

Qué no se puede afirmar desde el código

  • No se puede verificar desde el repositorio la retención, el acceso interno o las condiciones operativas de Apple CloudKit.
  • No se puede verificar el comportamiento del binario publicado ni la configuración de producción de push y CloudKit.
  • La etiqueta de privacidad declarada en App Store no se considera una prueba del comportamiento del código y no se reproduce aquí como “no recopilamos datos”.
